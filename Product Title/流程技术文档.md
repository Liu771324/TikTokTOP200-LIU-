## 2. 启动、登录与页面跳转

以下是后续工作台必须实现的行为。

1. 启动本地服务，使用 `127.0.0.1:8080`。如果端口被占用，停止启动并提示，不自动更换端口。用户同一时间只运行一套服务。
2. 先在系统默认的普通浏览器打开工作台，工作台不在调试 Edge 中打开。启动时检查 `9222`：存在可用调试会话时自动复用；未启动时先展示表格预览，用户在工作台点击“连接 Edge”后才用相同端口和调试用户数据目录启动 Edge。重复运行启动脚本时，若 `8080` 已运行本工作台，直接打开现有页面；仅被其他程序占用时提示错误。
3. 进入抖店后台首页。如果平台要求登录或验证，显示等待登录状态，由用户手动完成；完成前不执行商品查询或修改。
4. 登录完成后确保第一个业务标签页是抖店后台首页，再打开或复用“小猪批量修改”标签页。小猪页面若仍要求登录，由用户手动完成后继续。
5. 在小猪首页点击“多店铺关联”，再点击“多店删除/上下架/修改商品”，进入 `combainSearch/index` 页面。
6. 从该页的“查询店铺”区域读取店铺列表，交给本地工作台展示。

关闭启动脚本或调试版 Edge 时，工作台必须停止后续查询与保存、终止本地服务并释放 `8080`。关闭 Edge 后，其调试端口 `9222` 应释放。不要启动脱离启动脚本生命周期的后台服务；不要关闭无关的普通 Edge 会话。此退出行为是实现与验收要求，本次未运行工作台进行验证。

## 3. 工作台与店铺选择

工作台沿用 TOP200 的本地网页使用方式，提供读取或刷新店铺、勾选店铺、查看 Excel 分组、开始任务以及查看进度和结果的操作。

店铺必须从小猪页面动态读取，不能把本次看到的名称写成固定配置。每次启动默认全不选；至少选择一家店铺后才能查询和执行。开始任务时确定本次店铺范围，所有原标题查询都使用该范围。

商品状态选项从小猪页面动态读取，默认“所有”。用户可选择在售、下架、草稿箱、审核中、封禁、审核驳回、审核通过待上架（自主下架）、下架未提审（平台下架）。任务开始后锁定所选状态，全部分组、保存结果核对及查询恢复均使用同一状态；工作台执行结果和 JSON 记录本次状态。

## 4. Excel 读取与分组

只读 `标题.xlsx` 的 `Sheet1`。第一行为表头：A 列“原标题”，B 列“新标题”。不修改、覆盖或重新导出输入工作簿。

按表格行顺序读取：A 列有原标题时确定当前原标题；A 列空白时沿用上一个原标题。B 列非空值作为当前原标题对应的新标题，保持表格顺序，保留标题正文，不自动改写或截断。空新标题跳过并记录，不能用空值清空商品标题。若尚未出现原标题就出现新标题，报告输入格式错误并在执行前停止。

本次复核的实际数据为：

| 数据范围 | 含义 | 新标题数 |
| --- | --- | --- |
| `A2:B5` | 第一组原标题及其新标题 | 4 |
| `A6:B9` | 第二组原标题及其新标题 | 4 |
| 合计 | 2 组原标题 | 8 |

`Sheet2`、`Sheet3` 均为空，不参与处理。此前计划写成“7 个新标题”属于统计错误，本文件按实际工作簿修正为 8 个。

## 5. 查询、分配与逐件保存

1. 按 Excel 中原标题首次出现的顺序逐组处理，每次只查询一个原标题。
2. 在多店商品页面同步本次所选店铺与商品状态，把原标题填入“商品关键词”，点击“查询”。商品状态使用工作台选择（默认“所有”），其他查询条件保持空白，避免残留条件缩小结果。状态无效或页面选项已变化时，在查询前停止并要求重新选择。
3. 等待所选店铺全部查询结束，再读取结果。若店铺查询未完成或报错，停止并报告，不把不完整结果当作全部商品。
4. 所有查询返回的商品均参与分配，不额外要求当前标题与原标题完全相等。按页面显示顺序自上而下形成一个结果列表，跨店铺不重置新标题序号。
5. 在本组开始保存前记录商品顺序、商品 ID、所属店铺与当前标题；之后按商品 ID 定位对应行，避免编辑后行顺序变化导致改错商品。
6. 处理件数为 `min(查询结果商品数, 当前原标题的新标题数)`。第一个新标题对应第一件商品，第二个对应第二件，以此类推。
7. 点击对应商品标题的行内编辑入口，填入新标题，检查页面计数与校验提示，然后点击该行的“保存”。每件单独保存，确认结果后再处理下一件。
8. 本组结束后记录统计，再查询下一组原标题。

| 数量情况 | 处理规则 |
| --- | --- |
| 商品数大于新标题数 | 只修改前面的对应商品，后面多出的商品保持原样 |
| 新标题数大于商品数 | 修改到最后一件商品，后面多出的新标题不使用 |
| 两边数量相同 | 按顺序一一对应修改 |
| 查询无命中 | 记录无命中，继续下一组原标题 |

例如：第一组有 4 个新标题，当前查询结果有 3 件商品，分别属于茶漾甜小店、圣禾堂小店、花露香榭。按当前页面顺序使用该组前 3 个新标题，第 4 个不使用。若同一组查询到 6 件商品，则只改前 4 件，后 2 件保持原样。

## 6. 校验、重试与停止规则

页面标题编辑器显示“中文计 2，英文 / 数字计 1”，上限为 60。以平台实际计数和校验为准；不要简单使用字符串长度代替平台计数。发现新标题超限时不保存该商品，记录失败并跳过，继续下一件商品和下一条新标题，不自动截断。已成功保存的商品保留结果。

每次保存后核对同一商品的标题和页面反馈。失败时最多重试一次，总共最多两次保存尝试。若第一次保存结果不确定，先重新核对商品：已显示目标新标题则记为成功，不再提交；仍为旧标题且编辑上下文可靠时才重试。无法确定结果时停止并报告，不盲目重复提交。

平台明确拒绝保存、重试仍失败时，记录原标题分组、店铺名、商品 ID、目标新标题和失败原因，跳过该商品并继续下一件商品和下一条新标题，后续原标题分组继续处理。失败的标题已消耗，不再分配给下一商品。已成功保存的数据不自动回滚。保存结果不确定、登录或授权异常、查询失败、浏览器关闭或连接中断时仍停止后续动作。

失败商品和结果待核对商品自动写入 `reports` 下的 Excel 清单，工作台提供“下载失败 Excel”；商品 ID、店铺 ID 按文本保存，避免数字精度丢失。清单记录店铺名、失败原因、原标题查询词、新旧标题、表格行号和保存尝试次数，保留原有 JSON 完整结果。

结果记录至少包含：所选店铺、原标题分组、查询商品数、新标题数、实际保存数、商品 ID 与店铺、保存前后标题、成功或失败状态、未修改商品数、未使用新标题数、跳过项以及停止位置。这些是未来工作台应展示的进度与汇报内容，本次不创建任务数据文件。

### 后续实现验收场景

| 场景 | 预期结果 |
| --- | --- |
| Edge 未登录 | 等待用户登录，完成前不查询或保存 |
| 店铺列表刷新、未选择店铺 | 动态显示当前店铺；未勾选时不能执行 |
| 选择商品状态 | 查询只包含所选状态，全部分组沿用；执行时锁定并记录状态 |
| 同一原标题命中多个店铺 | 按整个结果列表顺序分配，不按店铺重新开始 |
| 4 个新标题、3 件商品 | 只保存前 3 个，第 4 个记录为未使用 |
| 4 个新标题、6 件商品 | 只保存前 4 件，剩余 2 件不改 |
| 查询命中非完全相同标题 | 仍纳入分配，符合用户确定的全部结果规则 |
| 无命中或新标题为空 | 跳过并记录，不保存空标题 |
| 新标题超过平台限制 | 不保存该项，记录失败，下一商品使用下一标题 |
| 单件保存明确失败 | 重试一次；仍失败记录并跳过，继续后续商品和分组 |
| 失败商品清单 | 自动落盘并可下载 Excel，商品 ID 文本精度保留 |
| 保存结果不确定 | 先核对商品状态，无法确认则停止 |
| 关闭脚本或调试版 Edge | 停止后续动作，本地服务退出并释放端口 |
| `8080` 已被占用 | 停止启动并提示，不自动换端口 |

当前文档阶段的验证只读取页面与输入文件，不提交真实商品修改；后续保存链路验收需按上述规则单独记录实际结果。

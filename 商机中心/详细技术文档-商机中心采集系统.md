# 抖店商机中心采集系统：详细技术文档

> 文档状态：当前实现
>
> 最后更新：2026-08-25
>
> 文档分工：本文记录当前架构、接口和数据规则。已发生故障的现象、根因、错误做法和排障顺序统一维护在《[商机中心数据采集-踩坑记录.md](./商机中心数据采集-踩坑记录.md)》；修改采集器前两份都必须阅读。

## 1. 目标与边界

系统连接用户已经登录的真实 Microsoft Edge，读取抖店商机中心真实类目，按用户勾选顺序串行采集多个类目的成交增长数据，并输出合并 Markdown、JSON 和 Excel 报告。

安全边界：

- 只连接 `http://localhost:9222` 的真实 Edge CDP。
- 不读取、复制、导入或解密 Cookie。
- 不并发操作同一个 Edge 页面。
- 采集过程中不刷新抖店页面。
- 登录和验证码由用户本人完成。

## 2. 架构

```text
启动采集.bat
  ↓
server.js + public/index.html
  ├─ category_discovery.js → 真实页面类目树
  ├─ task-store.js         → 任务快照和检查点
  └─ batch-runner.js       → 类目组合串行执行
        ↓
     collect_v4.js         → 现有单类目稳定采集流程
        ↓
report_output.js + export_excel.js
```

`collect_v4.js` 的金额、抽屉、增长、分页和重试算法保持单类目职责。批量层通过环境参数逐个启动现有采集器，采集器将单类目结果写入检查点，批量层负责合并和最终报告。

## 3. 类目发现

`category_discovery.js` 连接已有商机中心页面，读取页面自身已经加载并签名的 `shop_full_category/list` 响应。请求在已登录页面上下文中完成，不导出 Cookie。

每个节点保存：

```json
{
  "displayPath": "传统滋补 / 药食同源食品 / 茯苓",
  "segments": ["传统滋补", "药食同源食品", "茯苓"],
  "valuePath": ["1000002718", "1000002731", "..."]
}
```

创建任务时，服务端把前端提交路径映射回最近一次发现缓存，拒绝空类目、重复类目、伪造路径和过期路径。任务保存完整类目快照，后续续跑不依赖新的发现结果。

## 4. 任务与检查点

任务保存在 `data/tasks/`，未完成或含失败类目的检查点保存在 `data/checkpoints/`。JSON 使用临时文件加 `rename` 的原子写入方式。

一个类目对应一个组合：

```text
pending → running → completed
pending → running → stopped
pending → running → failed
stopped/failed → pending → running
```

规则：

- 同一时间只允许一个活动任务。
- 同一任务只执行一个当前类目。
- 类目完成后立即保存。
- 继续任务跳过 `completed`。
- 重试只重置 `failed`。
- 未完成类目重跑前清除该组合的旧部分结果，避免重复；其他已完成类目结果保留。
- 服务启动时把遗留 `running` 状态恢复为 `stopped`，等待用户继续。

## 5. 金额与数据口径

金额档位必须完整落入用户区间：

```text
档位下限 >= 最低金额
且
档位上限 <= 最高金额
```

高于上限跳过，进入区间后读取详情，低于下限结束。金额解析失败不能当 0 元。

商品详情切换“近 1 天”，读取今日成交和较上周期。正常增长反推昨日范围；增速快保留但昨日为 `-`；下跌、持平、无法解析和三次后无数据分别统计。保存前必须满足分类守恒。

## 6. 页面稳定性

- 禁止用 `document.querySelectorAll('tbody')[固定索引]` 定位商品表。
- 应按同时包含“搜索词”和“成交金额”的表头定位商品表，再按“成交金额”表头动态确定列号。
- 表体首行可能是表头占位行，应识别并排除，不能假设所有页面结构完全一致。
- 使用底部真实分页，不能只看顶部假分页。
- 翻页必须同时校验页码、完整行数和商品/金额指纹。
- 页码先变但内容未变时只等待，不重复点击。
- 排序必须先读取 `aria-sort` 或活动箭头，只在当前不是降序时点击；金额档位允许相等，但不能出现递增。
- 抽屉使用 `.aurora-drawer-open`，标签行不能误当金额。
- 继续使用固定等待、业务状态比较和有限重试的组合。

## 7. 报告

Markdown 主表固定包含“类目”列。Excel 包含：

1. `采集汇总`
2. `成交增长`
3. `失败记录`

完整和部分报告分别使用：

```text
选品报告-成交增长.md|xlsx
选品报告-成交增长-部分.md|xlsx
```

部分报告不覆盖上一份完整报告。历史 Markdown 和 JSON 保存在 `reports/`。

## 8. 接口

```text
POST /api/discover
GET  /api/tasks
POST /api/tasks
GET  /api/tasks/:taskId
POST /api/tasks/:taskId/pause
POST /api/tasks/:taskId/resume
POST /api/tasks/:taskId/stop
POST /api/tasks/:taskId/retry
GET  /api/tasks/:taskId/download?type=md|xlsx|json
```

旧 `/api/start` 和 `categories.json` 仅保留兼容，不是新页面正常流程。

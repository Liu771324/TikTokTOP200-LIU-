# 商机中心采集系统：交接文档

> 最后更新：2026-08-25

## 当前状态

多类目改造已经接入正式目录：

- 从已登录商机中心页面自动读取完整类目树。
- 前端支持搜索、复选、多选和已选数量。
- 一个任务串行执行多个类目。
- 每个类目完成后保存任务和检查点。
- 停止或服务重启后可继续，已完成类目跳过。
- 失败类目可单独重试。
- Markdown、JSON、Excel 合并输出，并给每条明细写入类目。
- Excel 提供 `采集汇总`、`成交增长`、`失败记录` 三个工作表。

现有金额档位、增长分类、商品三次重试、真实分页校验、暂停/停止和完整/部分报告隔离规则保持不变。

## 新增文件

| 文件 | 职责 |
|---|---|
| `category_discovery.js` | 通过真实 Edge 页面自身已加载的类目接口读取并规范化类目树 |
| `task-store.js` | 任务创建、原子 JSON 保存、检查点、服务重启恢复 |
| `batch-runner.js` | 按类目组合串行启动现有采集器、合并结果、生成任务报告 |
| `test/category_discovery.test.js` | 类目树、路径和规范化测试 |
| `test/task_store.test.js` | 任务顺序、检查点、恢复和失败重试测试 |
| `test/batch_runner.test.js` | 未完成类目重跑时的结果替换和统计测试 |
| `test/ui_smoke.js` | 本地页面真实类目读取、搜索和多选冒烟测试 |

## 主要接口

```text
POST /api/discover
GET  /api/tasks
POST /api/tasks
GET  /api/tasks/:taskId
POST /api/tasks/:taskId/pause
POST /api/tasks/:taskId/resume
POST /api/tasks/:taskId/stop
POST /api/tasks/:taskId/retry
GET  /api/tasks/:taskId/download?type=md|xlsx|json
```

旧 `/api/start` 和 `categories.json` 保留为兼容入口，新页面正常流程不依赖本地类目配置。

## 数据目录

```text
data/tasks/         完整任务快照
data/checkpoints/   未完成或含失败类目的检查点
reports/            历史 Markdown / JSON 报告
```

写入任务时先写临时文件再 `rename`，避免中途断电留下半个 JSON。

## 验证记录

- `npm run check`：30/30 自动化测试通过。
- 隔离端口页面冒烟测试通过。
- 真实 Edge 页面类目读取通过，平台当前返回约 6000 个可选节点，最多 4 层。
- 真实页面搜索“药食同源食品”能返回父类目和完整子路径，保存的路径可以重新定位。
- 未启动真实大规模采集；长流程仍应由用户选择类目和金额区间后发起。

## 安全红线

- 只使用真实 Edge CDP `http://localhost:9222`。
- 不复制、导入或解密 Cookie。
- 不刷新采集中的抖店页面。
- 不并发操作同一个 Edge 页面。
- 不修改 `备份/`、`交付/` 或 `Tiktok TOP200`。
- 不改变金额档位完整落入、近 1 天口径、分类守恒和分页稳定性规则。

# 数据目录迁移与磁盘清理实施计划

日期：2026-10-13。用户要求将视频、任务和浏览器资料从C盘迁到D盘，并清理本轮导致项目目录增大的重复产物。本次不实施代码混淆或收费授权。

## 实施步骤和通过条件

1. 盘点项目、发布包和构建目录，保留源代码、业务历史结果及未来构建需要的共享依赖。只删除本轮生成且可重建的旧发布副本和构建中间目录；逐个校验绝对路径及边界。
2. C盘用户目录`.scriptall-toolbox/settings.json`的小配置只记录数据位置，避免桌面宿主对AppData的重定向影响不同启动入口；默认兼容原有数据根目录。生产使用固定配置身份和旧版身份双锁，避免迁移后新旧实例同时写库。
3. 存储管理展示实际目录与剩余空间，通过系统文件夹对话框选择位置。存在运行、排队、暂停或读取操作时拒绝迁移；选择后明确退出，再次启动完成迁移。不开任意路径执行接口。
4. 启动迁移在数据库、Edge和WebView启动前完成：目标只允许新的空数据目录，拒绝与源目录/程序目录重叠及目录链接；校验可用空间，复制并逐文件SHA256核对，核对源没有变化，最后原子切换启动配置。复制中断可凭专用标记恢复，不能覆盖外来非空目录。
5. 复制或校验失败时继续使用原路径，不切换，不删除原数据；界面可重新选择。迁移完成后保留旧副本，确认新位置原任务/媒体/登录可用再清理。清理仅能针对启动配置登记的旧根，遇链接或未验证文件拒绝删除。
6. 本机目标使用`D:\电商工具箱数据`，用户无需输入路径。保留任务ID、相对媒体引用、浏览器及WebView配置；对含旧绝对内部路径的引擎恢复信息做专项检查，不能只移动数据库表面成功。
7. 聚焦测试：正常迁移、非空目标/重叠/目录链接、空间不足、复制中断恢复、失败不切换、旧目录清理保护；UI目录选择/取消/失败提示。一次源码界面及一次0.1.2冻结启动、升级验收即可，未改动业务采集规则不重新全量采集。
8. 真迁移前确认旧程序已正常退出。先保留C盘副本，启动读取D盘任务/结果并确认浏览器原会话可打开后，再清理旧副本。记录释放空间与剩余项目占用，提交、合并main、推送确认后删除开发分支。

## 风险边界

- 移动中的数据不能被另一个旧版实例改写；旧程序退出与固定单实例锁都是必要条件。
- 浏览器缓存后续仍会增长，但迁移后增长发生在所选数据盘；C盘仅有小配置及系统自身临时文件。
- 断开的数据盘不可静默回退成新空数据库，否则用户会误以为历史数据丢失；应提示恢复磁盘或修复数据位置。
- 程序安装位置与数据位置独立。本次会优先消除大体积运行数据占C盘的问题，程序仍可通过安装向导选择D盘。

## 3. 操作顺序和通过条件

1. 确认工具箱和专用浏览器退出；扫描当前目录，记录大小，保留用户任务与媒体。
2. 用现有DataLocation迁移机制将数据复制到新空目录，逐文件SHA256核对源和目标；最后切换启动指针。原目录暂时保留，复制失败不得切换。
3. 用已登记卸载器卸载旧程序，再使用SHA256一致的0.1.2安装器安装到新“程序”子目录。安装/卸载不能改动数据；检查快捷方式和卸载登记。
4. 聚焦验证：主库quick_check及外键、原任务与结果数量、原文件完整性；一次安装版启动smoke。复用未改动业务代码的既有采集证据，不重采榜单。
5. 新位置校验后，通过迁移机制清理已登记旧副本。清理前核对路径、拒绝链接并核验原可用结果的大小/SHA。旧程序通过卸载器移除，不手工复制安装目录或留下旧快捷方式。
6. 复测最终大小，记录证据，提交合并main并推送核对远端。容量检查及迁移验证预算约30分钟；遇到具体异常再扩大检查范围。

## 4. 小于5GB的约束

将“所有现有工具接入后的程序及必需运行时小于5GB”作为后续打包容量目标。沿用共享运行时、白名单收录源码、排除依赖开发副本与历史业务文件、只保留当前发布产物。每次版本发布记录安装后大小，不能靠把每个独立工具的完整开发目录直接塞进安装包实现聚合。

视频和浏览器资料随使用增长，不能承诺连同无限历史视频始终小于5GB。已有媒体去重、任务引用和可视化清理；继续沿用这些功能，保留用户对结果清理的决定权。本次仅按用户追加授权清理已识别的验收视频和测试记录，保留登录资料、原独立工具业务文件及其他项目，不增加未要求的容量配额。

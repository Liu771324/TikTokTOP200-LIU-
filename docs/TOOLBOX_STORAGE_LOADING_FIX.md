# 存储管理切换加载状态修复

日期：2026-10-13。

## 原因与范围

存储页在`storage.get_usage`、数据位置和导出位置查询全部完成后才替换内容区；导航和标题已先更新，因此期间会显示上一页。存储统计遍历数据文件，需要等待。查询失败时原实现也保留上一页内容。

仅修改存储页前端和对应样式：进入及刷新时立即用加载卡片替换内容，显示转圈和“正在统计存储占用”；查询成功再展示信息，失败显示可通过刷新重试的提示。三个独立只读查询同时发起。保留加载节点作为本次请求身份，已离开存储页或被更新请求替代时丢弃旧响应，避免旧查询反写。

差异检查发现任务列表和人工视频待选列表的旧请求也可能在切到存储页后写入内容，令加载节点失效；在这两处异步返回时补当前页面检查，人工视频同时检查原面板仍在内容区。存储/人工入口也拒绝离开页面后的旧操作回调触发刷新。其余同步工具表单不需要改动。

## 执行顺序

1. 修改前端等待顺序、加载与失败状态，补充匹配现有界面的转圈样式，兼顾减少动态效果偏好。
2. 检查异步路径及最终差异；沿用既有基础保护构建0.1.3，记录安装包及来源，不新增测试套件或采集样本。
3. 安装包准备完成后请用户退出工具箱，再升级到原统一目录；核对数据位置和数据库未被安装修改，打开正式安装版。
4. 完成后清理本次构建中间副本，更新交付记录，提交合并main、推送核对远端后删除开发分支。

本次为小范围界面修复及既有打包流程，检查约10分钟；不修改存储统计规则、业务采集和数据模型。

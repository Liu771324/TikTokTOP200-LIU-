# 总仓结构与分支约定

## 目标

`Script All` 是多个本地电商工具的源码库。工具之间可以面向不同工作流程，也可以采用不同技术栈。总仓统一管理代码入口和项目说明，不把业务功能合并成一个程序。

## 目录

第一阶段保留现有工具目录和启动路径。每个工具独立维护自己的代码、依赖清单、启动脚本、使用说明、测试和本地数据位置。总仓根目录的 README 作为工具目录索引。

只有在确有共享需求时才抽取公共模块；单个工具的修改不得顺手重构其他工具。

## 分支流程

1. `main` 保存已纳入工具库的集成版本。
2. 为一个工具开展开发时，从 `main` 创建 `tool/<工具标识>` 分支；新增工具也从 `main` 创建自己的分支。
3. 分支提交尽量限制在该工具目录及必要的仓库索引、忽略规则中。
4. 一个工具版本准备好后，提交 Pull Request 到 `main`。审查和合并后，工具源码进入集成库；后续该工具仍可继续使用自己的开发分支。
5. 每个工具按自己的命令构建和验证。总仓不要求所有工具使用同一个运行时或测试命令。

分支包含整个仓库的快照，工具之间的运行隔离由目录、依赖和数据位置实现。分支用于隔离开发和审查，不作为工具唯一的永久存放位置。

## 提交边界

纳入版本管理的内容包括源码、使用文档、依赖清单、测试、示例配置和必要的静态规则数据。不要提交真实商家表格、采集结果、日志、缓存、虚拟环境、`node_modules`、浏览器用户数据或本地生成的安装包。

打包文件和第三方二进制组件应独立评估体积、许可和分发方式。源码仓库只保留构建说明和必要的第三方声明；确需分发时再使用 GitHub Releases 或后续下载服务。

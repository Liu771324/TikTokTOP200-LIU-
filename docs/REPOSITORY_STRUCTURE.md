# 总仓结构与分支约定

## 总仓的作用

`Script All` 是面向抖音电商工作的本地工具库源码仓库。总仓保存独立工具源码、公共工具箱代码、文档与测试。各工具保留自己的业务规则，工具箱统一普通用户的操作界面、浏览器会话、任务和结果管理。

最新第一版目标是 Windows 桌面工具箱，首批包含商机中心、TOP200、自动短视频采集及人工视频工作台。当前技术文档已编写，工具箱实现尚未开始；已有源码继续按独立说明使用。先前“仅整理目录和索引”的第一版范围已被本设计替代。

详细设计见[工具箱技术方案](TOOLBOX_V1_PLAN.md)、[接口与数据约定](TOOLBOX_V1_CONTRACTS.md)和[实施与验收清单](TOOLBOX_V1_EXECUTION.md)。

## 目录规则

- 每个已有工具保留根目录下的源码目录、独立入口、说明和测试。首批迁移提取业务引擎并注入运行上下文，不一次性搬动全部源码。
- 新增公共桌面模块规划放在 `toolbox/` 下，管理界面、宿主、引擎适配、公共测试和发布脚本。该目录当前尚未实现。
- 总仓根目录的 `README.md` 是源码工具索引和工具箱文档入口。独立工具按自己的说明启动；工具箱的运行和发布约定以技术方案为准。
- 新工具应有独立目录和 `README.md`，说明用途、适用系统、运行要求、启动方法和数据保存位置。
- 保持已有工具目录名和启动入口稳定。确需改名或迁移时，同步更新总索引和工具内链接。
- 多工具确实共用的浏览器、任务、存储与桌面能力抽取到公共模块。工具专属筛选和采集规则保留在各业务引擎，不顺手修改未接入工具。
- 工具箱用户数据保存到 `%LOCALAPPDATA%/ScriptAllToolbox`，与源码和安装文件分离；旧工具独立运行模式在迁移期间保留原入口。

## 分支规则

- `main` 是集成分支。工具完成并合并后，源码留在对应目录中；克隆 `main` 可以取得已集成的工具。
- Git 分支保存的是整个仓库在某一时刻的版本，不是某个工具的永久容器。工具之间靠目录、依赖和数据位置保持运行独立。
- 一个工具或一项仓库级工作使用一个临时开发分支。默认命名为 `codex/<工作标识>`，例如 `codex/search-term`。新分支从最新 `main` 创建。
- 开发分支的改动应限于对应阶段的工具、公共代码、必要文档及忽略规则。整个工具箱第一版继续在当前开发分支按阶段提交。
- 开发完成后先合并到 `main`，再推送 `origin/main`；远端推送成功后删除已合并的本地开发分支。不要在合并或推送前删除分支。
- 当前仓库级整理继续在 `codex/ecommerce-tool-library` 分支进行；完成后按上述顺序合并和推送，再清理该分支。

具体命令见 [开发、合并和推送流程](DEVELOPMENT_WORKFLOW.md)。

## 文件与分发边界

源码仓库保留源码、使用文档、依赖清单、测试、示例配置和必要的静态规则数据。用户表格、采集结果、日志、缓存、虚拟环境、依赖安装目录、浏览器用户数据和本机打包产物不应作为源码提交。

当前独立工具按自己的说明安装依赖。目标工具箱第一版提供共享运行环境的 Windows 安装包，不包含开发数据、登录资料或各工具重复运行时。安装包不作为源码文件提交；未来收费、服务器分发和在线更新另行设计。

## 2. C盘增长的处理方案

当前安装向导可选择其他程序目录，但运行数据仍固定使用LOCALAPPDATA。仅把exe装到D盘不会迁移视频和浏览器资料。

建议下一步增加可视化“数据保存位置”：

1. 用户在存储管理中通过系统文件夹选择框选盘，界面显示剩余空间；不要求输入路径。不假定其他电脑一定有D盘。
2. C盘只保留一个很小的启动配置，记录实际数据位置；任务、视频、浏览器及WebView资料随数据根目录保存。
3. 迁移须在任务、读取操作与所属浏览器全部正常结束后进行。关闭数据库连接，复制并校验数据，成功后切换配置、重启并验证原任务和登录。失败保留原目录及原配置。
4. 不使用目录链接伪装迁移，不直接移动运行中的SQLite或浏览器配置。切换成功前不删除原数据，旧目录清理作为独立可确认步骤。

这是需要独立实现及验证的数据迁移功能；本次没有擅自迁移现有数据或改变其路径。

## 3. 当前包的逆向难度

**当前包不具备有效的源码保密能力。**

- Inno Setup是安装器；PyInstaller主要负责分发Python运行环境，并非加密器。
- 安装目录内的商机/TOP200/视频JavaScript、Node适配器和前端文件是可读文本，业务逻辑可以直接查看。
- 下载器核心目前还作为.py资源交付；其余Python模块即使封装成字节码，也不能认定无法提取或分析。
- SHA256清单用于核对文件完整性，不能隐藏代码，也不能替代可信发布者签名。当前程序和安装器尚未签署发布者代码签名。
- 本次GitHub匿名可见性查询返回403，未能确认仓库公开/私有状态。若以后采用闭源收费分发，应先确认源码仓库及历史提交的访问范围；混淆安装包不能保护已经公开的源码。

## 4. 建议采用的保护层次

| 层次 | 建议措施 | 能达到的效果与边界 |
| --- | --- | --- |
| 本地发布基础保护 | 核心Python使用Cython或Nuitka编译为Windows原生模块；发行包不再包含对应.py、构建中间C文件、调试符号和开发源码映射 | 提高还原成本，仍可分析机器码、内存与可见常量 |
| JavaScript发布处理 | 自有业务代码在构建暂存区打包并适度混淆，仓库开发源码保持可读；不改第三方依赖及许可证 | 阻止直接阅读原始源码，不能保证无法去混淆 |
| 收费与授权 | 私钥只在服务器；客户端验证服务器签发的授权。需要保密且适合联网执行的规则放服务器 | 减少向客户端交付的秘密；客户端本地检查仍可能被修改，离线功能仍可被分析 |
| 正式发行 | 使用可信发布者代码签名、受控下载来源及独立验收 | 有助于验证来源和发现篡改；不等于防逆向或防破解 |

不建议仅改成单exe、给压缩包设密码、把解密密钥硬编码在客户端，或只增加UPX压缩后宣称防破解。

## 5. 最小实现顺序与通过条件

1. **先改变发布输入。** 建立独立的受保护构建暂存区，Python核心以.pyd交付，明确列出哪些自有JS经过处理；不在源码树就地覆盖或混淆。编译器、下载缓存和中间文件放D盘构建目录，避免为了保护代码又向C盘安装大量构建缓存。
2. **处理浏览器执行边界。** Playwright的page.evaluate及其他序列化函数会在浏览器执行；混淆器若把字符串解码等辅助函数提到Node全局，浏览器会找不到它们。必须单独处理此边界，禁用会破坏自动化的反调试、自防御及域名锁功能；页面必须执行的代码仍对终端可观察。
3. **限定核验。** 检查发行包没有受保护Python的.py和原始JS副本；运行相关打包、工作者和浏览器函数边界测试，再做一次冻结启动及四工具最小真实样本。已有不受影响的安装/卸载证据不重复全量验收。
4. **再做收费系统。** 明确联网/离线授权需求后才加入服务器，不把本机验收版临时改成必须联网的客户端。

建议以“提高普通复制与直接阅读的成本”为近期目标，不承诺绝对防逆向。当前0.1.1安装包保持已验收行为，保护版需完成上述构建和兼容性验证后再替换。

## 6. 官方依据

- [PyInstaller源码隐藏说明](https://pyinstaller.org/en/stable/operating-mode.html#hiding-the-source-code)：字节码可能被反编译；可进一步编译模块。
- [Nuitka使用方式](https://nuitka.net/user-documentation/use-cases.html)：支持模块编译，原生扩展不等于所有字符串或密钥保密。
- [javascript-obfuscator](https://github.com/javascript-obfuscator/javascript-obfuscator)：提供发布混淆选项；激进选项可能影响性能或兼容性。

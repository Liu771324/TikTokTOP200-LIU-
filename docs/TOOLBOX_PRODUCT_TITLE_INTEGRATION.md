# 商品标题工作台接入技术方案

日期：2026-10-15。开发基线：`856dafc`（工具箱 0.1.5）。分支：`codex/product-title-integration`。

## 1. 本轮范围与完成标准

用户确认接入商品标题工作台；成本助手仅评估，不接入、不改业务库。原独立标题工具保持可运行，工具箱使用迁入 `toolbox/engines/product-title` 的核心，发布包不包含旧服务器、启动脚本和独立前端。

完成标准：普通用户可选表、读店铺、选商品状态、预览具体商品的新旧标题、确认提交，在任务中心查看进度、停止、查看结果并导出报告。原四工具使用原参数、存储和浏览器队列。成本评估另见 `TOOLBOX_COST_INTEGRATION_ASSESSMENT.md`。

这是跨宿主、Node、平台写操作、界面及安装包的 Large 变更。验证预算约 45 分钟：引擎与宿主隔离样本、界面模拟桥接、发布完整性及冻结启动各一次，最后一次独立审查；发现实质问题才针对性追加。真实商品保存由用户在界面明确确认触发，开发验证不自动修改商品。

## 2. 现有流程及复用边界

- `Product Title/workbook.js`：SheetJS 0.20.3 读取 `.xls/.xlsx`，只取 `Sheet1` 的 A、B 列；首行为“原标题”“新标题”，空 A 沿用上一原标题，空 B 跳过；拒绝公式与原标题换行，不截断、改写标题。
- `browser.js` 的 `ShopBrowser`：抖店登录、小猪多店商品查询、按 ID 唯一定位、行内编辑、平台计数及返回结果核对。
- `task.js`：分组分配、成功/未改/失败/不确定记录；工具箱改为先冻结分配计划，再执行计划，避免预览后重排分配。
- 冻结预览与旧逐组即时执行存在语义差异：多个原标题查询词若命中同一店铺同一商品，整份预览拒绝，提示调整重叠查询词；不会对同一商品安排多次修改，也不悄悄跳过重叠项。
- `report.js`：失败商品 Excel（商品/店铺 ID 按文本）。另保留完整 JSON 作为审计报告。
- 禁止迁入旧 `server.js`、`public/`、固定 8080/9222 监听、独立启动 Edge 及 `Browser.close` 全会话关闭行为。

## 3. 用户流程

1. 点击“选择标题表格”，系统选文件对话框只接受 `.xls/.xlsx`，上限 25 MiB。宿主读取一次快照，复制到内部临时目录并计算 SHA256；原表不覆盖。界面显示文件名、标题组数、新标题数、跳过行及首屏预览。
2. 点击“读取店铺和商品状态”。复用专用 Edge 的浏览器 FIFO；只访问抖店与小猪既有业务页。未登录时返回可执行的登录提示，不在短操作中无限等待。
3. 默认不选店铺；商品状态从实时页面读取，默认“所有”。选好后点击“预览商品修改”。后台只查询，按查询显示顺序分配新标题，生成完整冻结计划。商品多于标题的保留、标题多于商品的记录未使用。
4. 显示匹配数、拟修改数、未修改/未使用数，以及具体店铺、商品 ID、原始标题、目标标题和 Excel 行号；列表分页。更换表格、店铺或状态使旧预览失效。
5. 点击“确认修改商品标题”后，宿主弹出确认说明（影响范围、数量、无法自动回滚）。仅此动作创建写入任务。任务中心持续显示结果，停止后不执行后续商品。

## 4. 宿主与协议

### 4.1 专用桥接操作

| 操作 | 入参 | 结果 / 约束 |
| --- | --- | --- |
| `title.choose_input` | 无 | 原生选文件；返回宿主导入 ID、文件名与分组摘要，不接收网页任意路径 |
| `title.preview` | `inputId, shops, productStatus` | 加入浏览器队列，生成冻结商品计划；店铺与状态在业务页面再核验 |
| `title.plan_page` | `token, offset, limit` | 读取内存中计划引用并分页，只返回允许的展示字段 |
| `title.create` | `token` | 校验摘要、十分钟有效期和一次性 token，再弹确认；创建成功后消耗 token |

普通 `tasks.create` 对 `product-title` 拒绝，避免绕过预览/确认。工具列表增加描述符，支持停止，不支持暂停、跨进程继续、重试失败项。重新操作必须重新预览，不能重放旧任务。

### 4.2 Node 适配器操作

- `title_input`：无浏览器，读取宿主复制的工作簿，校验大小、行数上限及 SHA256，输出摘要；全输入在内部快照，协议消息不返回无限数据。
- `discover`：返回实时 shops、productStatuses；仅使用 `context.browser.endpoint`。
- `title_plan`：只读查询并冻结精确商品分配，完整 JSON 写入本次 `context.scratchRoot`；仅返回计划文件及摘要，宿主复制到 `scratch/title-plan-<ID>/plan.json` 并登记 token。最多 10,000 行标题/商品记录、100 组原标题、20 MiB 计划，重复商品分配、缺失 ID、超限或查询不完整均拒绝。只读预览最多等待 15 分钟，界面显示排队/读取状态。
- `run`：参数仅 `planId, planSha256`；从宿主数据根内固定位置读取并验哈希，逐组重新查询定位既定商品，标题或范围变化即停止，绝不按新顺序重新分配。
- `read_results`：读取既有 engine-state envelope，分页展示全部商品，不获取浏览器、不新建任务目录。

计划含 `engine`/版本、来源文件名和摘要、shops、productStatus、groups、items、统计；每个拟处理项固定 ID、店铺、before、target、Excel 行号。宿主校验计划身份、大小、计数、唯一键及摘要，拒绝非内部路径。任务参数和检查点不保存平台登录凭据。

## 5. 停止、故障与重复提交控制

- 宿主启动恢复时，标题 `queued` 任务转失败，正在执行任务按现有恢复逻辑转意外中断。没有任何自动保存重放。
- 点击保存前持久化当前项 `saving` 与尝试次数；落盘失败则不提交。明确失败最多重试一次，重试前仍检查停止标志；未知结果不重复提交。
- 已点击的保存允许完成响应/页面核对。原实现响应 30 秒、页面核对 10 秒，不能沿用宿主通用 10 秒停止硬超时；在途核对有界 60 秒以内，标题单独使用 75 秒停止硬超时、退出最多等待 80 秒覆盖报告收尾。
- 停止后禁止新提交；仅对当前在途项做有界只读核对，确认失败/成功/未知写入检查点。未知必须展示“待核对”，不算成功，也不自动重试。
- 取消后普通 SDK 输出/登记仍保持原限制；新增标题专用报告收尾登记，只接受 Excel/文本，不允许媒体及其他工具使用。完整 checkpoint 为报告故障时的结果依据。
- 宿主强杀、进程断电可能留下 `saving` 项：结果读取时显示待核对提示。成功保存无法自动回滚，报告保留原/新标题用于人工处理。

## 6. 隔离、资源和发布

- 所有标题读取/写入使用既有浏览器 FIFO，其他采集工具排队；不另开服务端口或第二套浏览器资料。
- 只新增 SheetJS 锁定依赖，复用现有 Node、ExcelJS、Playwright、Python 和 Edge。`.xls` 支持不能由只读 `.xlsx` 替代。
- 引擎、适配器加入发布精确白名单及基础 JS 混淆；不打包独立工具、用户表格、测试或依赖副本。第三方许可随包登记。
- 文件快照/计划位于内部 scratch，活动任务期间不可清理；结束后现有“清理缓存”可清理。任务 checkpoint、JSON/Excel 报告随任务保留，可通过存储管理删除；输入表格正文不额外长期备份。
- 升级仍安装到 `D:\前端\ai\电商工具箱\程序`，沿用同总目录 `数据`，不迁移成本助手 DB。保留 0.1.5 回溯点。

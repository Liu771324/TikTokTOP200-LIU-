# 视频引擎与下载核心交接规则

2026-10-14 从旧短视频需求方案、使用说明及现有工具箱适配器提取。自动/人工视频业务模块位于 `toolbox/engines/video`，公开视频 Python 核心位于 `toolbox/engines/downloader`；核心和许可从外部独立工程按文件复制并核验 SHA-256，未迁入独立 GUI、服务器、FFmpeg、产物和输出。

- 自动短视频按平台原始排名前 200 名扫描；类目、品牌、平台预设周期单选。趋势仅首次上榜，或上升及首次上榜。动态读取页面周期并保存所选口径。
- 先激活短视频榜再读取选项或应用筛选；页面标题可能仍为商品卡排行，以活动标签和表格为准。播放器兼容 auxo/ecom 容器，不能误取页面中无关 video。
- 每商品依页面顺序处理候选，最多保存四条不同视频，并尽量达到两条；重复后继续检查 +N 中后续候选，不能保证一定存在两条。媒体候选顺序执行，单条失败不阻断其他候选。
- 罗盘卡片新开抖音网页时关闭该次新标签并记录失败，不能把它视为已获取播放器媒体。人工公开链接走独立 Python 解析核心，人工罗盘候选带页面/商品身份，页面变化须重新读取。
- 视频先按 SHA-256，再按抽样画面比较。开头约5秒至少80%能对齐，或较长指纹至少12帧且较短指纹80%可按顺序对齐，可判视觉重复。文案相同不证明视频相同；无视觉分析时仍保留文件哈希判断。
- 工具箱使用共享媒体登记与任务引用；自动/人工适配器传入 managed runtime，不得调用旧 `prepareVideoHashIndex` 扫描并删除共享历史视频。任务删除通过引用计数处理。
- 下载先写临时文件，校验非空后登记；音视频分轨时使用共享 FFmpeg stream copy 合并/封装。取消、超时与进程异常需要回收子进程，保留已登记结果，清理未完成临时文件；不在取消后重新发起备用解析。
- 视频成功但文案缺失时保留视频、记录问题，不创建空文案。名称优先使用商品及候选文案共同包含的商品词，清理不安全字符，无合适词则回退商品标题；泛场景词不能替代商品主体。
- 检查点关联任务、attempt及候选登记。恢复校验榜单总数、每页条数和商品位置，发生变化要求新建任务。每次重试不重复登记已提交候选。
- 真实登录由用户完成，宿主管理 CDP 与浏览器队列。只获取正常播放流程提供的媒体，不绕过平台验证。迁移的 `shared/edge.js` 仅供尚未接入的搜索词独立工具继续使用，不是工具箱宿主入口。

现有测试迁入 `toolbox/tests/engines/video` 和 `toolbox/tests/engines/downloader`。DOM 测试仅启动本地 Edge、加载内存 fixture 并拦截外网请求；下载核心测试只使用本地 HTTP、模拟解析与进程。

## 3. 目标结构

```text
toolbox/
  engines/
    downloader/         # Python下载核心及许可证
    business/           # Python API解析/采集、报告与适配器
    top200/             # 仅仍被工具箱引用的Node业务模块
    video/              # 自动/人工视频共用业务模块
  python_worker.py      # 与原NDJSON协议一致的Python后台入口
  host/                 # 原统一浏览器、调度、存储及桌面桥接
  node/                 # 视频/TOP200 worker和适配器
  tests/                # 隔离临时目录、模拟API与必要迁移回归
```

Python任务使用独立隐藏进程，复用宿主现有工作者通信与浏览器队列。冻结程序增加专用后台启动参数，进入后台前不创建桌面窗口。就绪、心跳、状态、结果登记和任务身份检查沿用现有协议；不另建本地HTTP服务器或浏览器资料。

认证只从受管Edge的当前已登录会话获取并保留在子进程内存。只连接宿主授予的CDP端点，不读取cookie.txt、不自动连接其他9222浏览器。API请求只发往已有采集器使用的平台固定HTTPS接口；登录失效、限流、验证码停止请求并提示处理，不尝试绕过。

- 类目读取将官方三级树转换成现有界面接受的`displayPath/segments/valuePath`，每条任务保存官方ID。
- 类目串行，指标小批量并发，分页等待有界且可响应控制；复用Python金额、方向和分类检查。保留精确数据与档位展示，过滤使用明确金额区间，不用推测值伪装平台原值。

- 报告使用统一staging和资产登记，覆盖同任务报告角色，避免每次暂停创建大副本。只记录业务数据及必要诊断，认证、签名URL和Cookie不进入检查点/日志/报告。

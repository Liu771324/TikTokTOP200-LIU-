# 成本助手接入稳定性评估

日期：2026-10-15
状态：**仅评估，暂不修复、暂不接入工具箱。**

## 1. 范围与结论

本轮依据用户指出的三类问题调查：聚水潭表格格式尚未确定、运费模板设置页不清晰、成本系统运行不稳定。商品标题工作台接入独立推进，不依赖成本助手整改。

结论：成本助手已有可复用的数据导入、成本计算、备份回滚和只读扩展能力，但应先稳定独立系统，再接入工具箱。当前不能把历史自动回归记录等同于本次实机验收，也不能仅凭“服务不可用”提示断定后台进程退出。

本轮只阅读文档和源码，没有修改成本助手代码、启动服务、执行测试、读取真实数据库或原始业务表、运行迁移、清理备份。本文所列代码行号以评估时源码为准。

## 2. 聚水潭表格与导入契约

### 2.1 当前实现

当前成本来源是一份普通商品表与一份组合商品表的配对全量导入，未启用聚水潭正式 API。桌面选择器仅接受可读取的 `.xlsx`，单文件上限 16 MB；XLSX 安全检查限制展开体积、条目数和数据行数。

依据：[版本边界](<../Cost Accounting(成本价）/docs/AI执行限制与版本边界.md>)第 41 行；[桌面导入入口](<../Cost Accounting(成本价）/cost_sync/desktop_app.py>)第 184–204 行；[XLSX 安全限制](<../Cost Accounting(成本价）/cost_sync/xlsx_safety.py>)第 7–19 行。

解析器要求仅一个工作表，第一行为表头；允许列顺序变化和额外列，但必填列名必须精确匹配。编码必须为非空文本，不能用数字型编码推测原始前导零。商品状态仅接受“启用”“禁用”“停用”。

依据：[商品表解析](<../Cost Accounting(成本价）/cost_sync/catalog_import.py>)第 335–398 行。

### 2.3 建议先锁定的格式契约

取得原始导出脱敏样表后，固定下列约定并使说明、解析器、预览提示与测试一致：

1. 聚水潭具体导出页面、导出选项、普通表与组合表的识别方式。
2. 必填列、可选列、明确支持的兼容别名、工作表及表头位置。
3. 编码保持文本和前导零，SpreadsheetML 转义仅按现有单次解码规则处理；不增加模糊 SKU 匹配。
4. 成本含税/未税口径，空值、零、负值、公式及缓存缺失规则。
5. 组合成本权威字段、明细差异显示与阻断规则。
6. 可靠的同批次标记。缺少证据时明确显示“无法验证同批次”，不声称已确认。
7. 完整快照与筛选/增量导出的区别。当前发布会以导入快照重建商品库，不能把局部导出当完整数据。

### 2.4 现有导入保护应保留

现有流程包含预览、不可猜测凭证、输入字节留存、SHA-256 复核、数据库版本复核、写前备份、暂存数据库及启用商品 Excel、发布校验与更新历史。确认写入时不会仅相信前端提交的摘要。

依据：[导入会话](<../Cost Accounting(成本价）/cost_sync/local_api.py>)第 190–288 行；[快照发布](<../Cost Accounting(成本价）/cost_sync/catalog_import.py>)第 151–247 行。

## 3. 运费模板设置与计算

### 3.1 当前页面与业务边界

页面同时提供模板列表、首重/续重编辑、地区价格、重量试算和商品绑定。绑定对象为“店铺 + 商品 ID”，同商品全部 SKU 共用；未列地区使用基础价格，“全国包邮”不代表内部运费为 0。

依据：[运费页面](<../Cost Accounting(成本价）/cost_sync/webview_static/index.html>)第 306–379 行；[运费计算](<../Cost Accounting(成本价）/cost_sync/shipping.py>)第 194–240 行。

当前模型不能表达禁运地区，不支持把按件运费静默转换为按重量运费。是否增加这些能力需要用户确认业务口径。

依据：[版本边界](<../Cost Accounting(成本价）/docs/AI执行限制与版本边界.md>)第 72 行。

### 3.2 已确认细节问题

## 5. 后续接入方案

成本助手适合成为长期运行的本地业务子系统，其导入和配置写入与普通采集任务的生命周期不同。建议未来在独立系统整改通过后：

1. 在工具箱统一数据根目录内设置专用 `cost` 子目录，保留独立成本 SQLite，不把成本表混入工具箱任务数据库。
2. 复用 `catalog_import`、`mapping_import`、`shipping`、`service_fee`、`true_cost`、`update_history`、`update_rollback`，保留既有数据语义。
3. 由工具箱可信桥接承载文件选择、预览、确认、配置和恢复；本机 HTTP 服务仅供扩展只读查询。
4. 由宿主管理成本服务，明确唯一服务所有者、端口冲突、数据源身份、退出与重启恢复策略。
5. 单独设计独立版数据迁移与回滚。真实库迁移需明确源库、目标库、备份与用户确认，不能把本轮评估视为迁移授权。
6. 复用工具箱运行时，不嵌套整个独立安装包；[依赖声明](<../Cost Accounting(成本价）/pyproject.toml>)第 5 行要求 Python ≥ 3.13，接入前需核对冻结运行环境和依赖兼容性。
7. 使用空业务初始化构建通用安装包，保留严格 SKU 匹配、Decimal 金额、缺失组件分别展示、扩展只读等边界。

以上均为建议方案，不代表本轮已实现。

## 6. 修复顺序与接入准入条件

### 第一步：确定表格契约

获取脱敏原始样表，确认普通/组合字段、成本口径与完整快照规则；修正文档与代码必填字段偏差，确定同批次证明和无法验证时的提示。

准入证据：两类正式样表与明确支持的变体能够稳定预览；缺列、错误编码、日期冲突、组合冲突、输入变更和局部快照有明确处理结果。

### 第二步：整理运费设置

明确模板、试算和商品绑定操作顺序，统一正式计算与试算，修复删除规则后的刷新，确定地区标准及插件查询使用的地区来源。

准入证据：首重/续重小数边界、特殊地区、空重量估算、模板停用、未绑定商品、保存取消及保存影响范围均可解释；不支持的按件或禁运明确说明。

### 第三步：定位实际运行故障

先核对用户实际版本、数据目录和日志，再在隔离库复现导入、插件查询、页面刷新、关闭/重启等行为。记录每个环节耗时、锁等待、服务身份和异常。

准入证据：能区分服务停止、查询暂慢、部分商品配置缺失、旧版不兼容和错误数据源；正常工作流连续运行无不可解释的状态跳变。

### 第四步：验证写入与恢复边界

使用隔离合成数据验证预览取消、过期凭证、输入变化、并发更新、备份失败、发布失败、回滚和服务退出。强杀恢复验证需单独记录覆盖范围。

准入证据：失败不破坏上一份完整数据；历史、备份和恢复一致；业务操作不能被普通网页或只读扩展执行。

### 第五步：再实施工具箱接入

前四步通过并得到用户接入授权后，实施宿主桥接、专用数据目录、唯一成本服务和空业务分发。真实数据迁移、旧安装库升级及真实成本抽查分别留下证据。

当前准入状态：**未满足，暂不接入。** 本轮不会对以上修复或验收作完成声明。

# 独立采集脚本设计方案

> 状态：旧方案，已由《技术方案-API单类目全量分类采集》替代
> 说明：本文记录早期单文件 Python 直连脚本设想，不再作为当前正式实现依据。
> 目标：不依赖浏览器、不依赖 AI，一条命令完成采集+分类+生成Excel

---

## 一、基本思路

用 Python `requests` 库直接调用抖店商机中心的两个内部 API，复用登录 Cookie 完成认证，无需打开浏览器。

核心就两个接口：
1. **列表接口**：翻页拉商品列表（每页18条，含 clue_id、30天成交）
2. **指标接口**：按 clue_id 拉近1天成交金额和环比

实测这两个接口**不需要 a_bogus / msToken / verifyFp 等签名参数**，在已登录状态下直接 POST 即可返回数据。

---

## 二、前置条件：获取 Cookie

脚本唯一需要手动准备的东西，约每7-30天换一次（Cookie 过期时）。

**获取步骤：**
1. 电脑浏览器登录抖店后台（fxg.jinritemai.com）
2. 按 F12 打开开发者工具 → Network 标签
3. 刷新商机中心页面
4. 找到任意一个发往 `fxg.jinritemai.com` 的 POST 请求
5. 在请求头里复制 `Cookie:` 后面的整段字符串
6. 粘贴到脚本同目录的 `cookie.txt` 文件里

脚本启动时自动读取 `cookie.txt`，不需要改代码。

## 三、脚本结构

单文件 `collect.py`，不引入额外依赖（只用 `requests` + `openpyxl`），分以下模块：

```
collect.py
├── 配置区（顶部常量）
│   ├── FIRST_CID = 1000002718        # 传统滋补类目ID，换类目改这里
│   ├── STOP_AMOUNT = 750000           # 30天成交低于此值停止（元）
│   ├── PAGE_SIZE = 18                 # 每页条数
│   ├── PAGE_INTERVAL = 20             # 页间等待秒数
│   ├── BATCH_SIZE = 6                 # indicator并行数
│   └── OUTPUT_DIR = "./output"        # 输出目录
│
├── API 封装
│   ├── fetch_page(page) → list[dict]  # 拉一页列表
│   └── fetch_indicator(clue_id) → dict # 拉单个商品近1天指标
│
├── 数据处理
│   ├── classify(item) → str           # 分类：下跌/上涨/持平/999.99%+/无法确认
│   ├── estimate_yesterday(today, hb)  # 反推昨日成交档位
│   └── merge_results()                # 合并+去重+过滤
│
├── 输出
│   ├── save_checkpoint()              # 每5页存一次检查点JSON（断点续传）
│   ├── gen_excel()                    # 生成多sheet Excel
│   └── write_log()                    # 运行日志
│
└── main()
    ├── 读 cookie.txt
    ├── 从检查点恢复（如有）
    ├── 循环翻页直到 STOP_AMOUNT
    ├── 每页：拉列表 → 拉indicator → 存检查点 → 等20秒
    └── 生成 Excel
```

## 四、采集流程

```
启动
 │
 ├─ 读取 cookie.txt（不存在则提示并退出）
 ├─ 检查 output/checkpoint.json 是否存在
 │   └─ 存在则从上次页码继续（断点续传）
 │
 ├─ 循环 page = 起始页, 起始页+1, ...
 │   │
 │   ├─ POST real_time_list 拉一页列表
 │   ├─ 对18条商品 POST indicator（6个一组并行）
 │   ├─ 追加到结果集
 │   ├─ 写检查点 checkpoint.json
 │   ├─ 打印进度：第N页，18条，当前最低30天成交¥XX
 │   │
 │   ├─ 本页最后一条 pay_30d < 750000？
 │   │   └─ 是 → 停止翻页
 │   │
 │   └─ sleep 20秒
 │
 ├─ 过滤 pay_30d >= 750000
 ├─ 按 pay_1d_hb 分类
 ├─ 反推昨日成交档位
 ├─ 生成 Excel（全部+分类sheet）
 └─ 输出统计摘要
```

## 五、关键逻辑（与本次一致）

### 分类规则
| 分类 | 条件 |
|---|---|
| 下跌 | `pay_amount_hb < 0` |
| 上涨 | `0 < pay_amount_hb < 9.9999` |
| 持平 | `pay_amount_hb == 0` |
| 999.99%+ | `pay_amount_hb >= 9.9999` |
| 无法确认 | `pay_amount_hb is None` |

### 昨日反推
```
昨日 = 今日成交(精确值) ÷ (1 + 环比)
```
结果映射到平台档位（小于¥50 / ¥50-¥100 / ... / ¥7500万-¥1亿）。

### 去重
按 `clue_id` 去重，防止翻页边界重复。

## 六、风控策略

1. 页间固定等待 **20秒**
2. indicator 接口最多 **6个并发**
3. 请求头带 `Referer: https://fxg.jinritemai.com/ffa/bu/NewBusinessCenter`
4. 请求失败自动重试3次（间隔5/10/20秒递增）
5. 连续5页请求失败则暂停，提示可能Cookie过期或被限流
6. 检查点机制：中途断了下次自动续传，不重复采

## 七、输出文件

```
output/
├── 传统滋补_商机采集_YYYYMMDD.xlsx   # 最终Excel（6个sheet）
├── checkpoint.json                   # 断点续传检查点
└── collect.log                       # 运行日志
```

Excel 结构与本次交付的完全一致：
- 全部数据（按30天成交降序）
- 下跌 / 上涨 / 持平 / 999.99%+ / 无法确认（各一个sheet）
- 列：序号、搜索词、品牌、类目、今日成交、昨日成交、日环比、分类、30天成交、需供比、在线商品量、标签

## 八、换类目方法

1. 浏览器打开商机中心，选目标类目
2. F12 → Network → 翻一页
3. 找到 `real_time_list` 请求，看请求体里的 `first_cid`
4. 改脚本顶部 `FIRST_CID` 常量
5. 同时改 `STOP_AMOUNT`（想要的30天成交阈值）

---

## 九、风险与限制

| 风险 | 应对 |
|---|---|
| Cookie 过期（接口返回登录页/401） | 脚本检测到非JSON响应时提示重新复制Cookie |
| 接口加签名校验（目前不需要） | 若后续加了 a_bogus 校验，需补签名逻辑或退回浏览器方案 |
| 请求被限流（429/空数据） | 退避重试，连续失败则暂停 |
| 类目ID变化 | 每次换类目从浏览器确认 first_cid |
| 平台档位调整 | 档位映射表写在脚本里，变化时手动更新 |

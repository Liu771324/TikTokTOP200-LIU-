# 成本助手操作文档

本项目把商品基础成本导入本机 SQLite，由桌面成本助手管理一个生效成本目录、运费、服务费和抖店店铺映射；Edge 扩展只在已支持的抖店页面读取最低到手价，并通过本机只读接口显示成本对比。

配套文档：[详细技术文档](聚水潭成本价同步-技术设计文档.md)、[问题记录](docs/问题记录.md)、[AI 限制](docs/AI执行限制与版本边界.md)、[项目状态与待办](docs/项目状态与待办.md)。

> 独立发布版本（2026-10-19）：客户端 0.2.0、扩展 0.1.1。包含通用成本表导入、发布恢复保护、服务身份与扩展自动重连、运费 Decimal 试算和分页，以及最新运费布局和侧栏排序。正式界面为七页，仍未接入工具箱。安装包使用空白初始化库，升级保留原安装数据；具体本机同步结果见[项目状态](docs/项目状态与待办.md)，此前源码验收见[实施记录](../docs/COST_ASSISTANT_RECTIFICATION_EXECUTION.md)。

## 新版源码：通用成本导入

1. 在“今日成本更新”选择 `.xlsx`、`.csv` 或 `.tsv` 成本表。旧 `.xls` 请先另存为 `.xlsx`。
2. 核对原始预览，选择工作表、前 50 行内的表头、文本编码和分隔符。列位置变化时重新读取。
3. 对应商品编码、基础成本列，可选名称和状态列。自动候选仅用于辅助，歧义时手动选择。编码须为文本，系统保留前导零及内部字符，不猜测数字编码。
4. 填写来源，确认同一套 SKU 身份及“人民币、单个销售 SKU 的基础成本”。默认增量更新，未出现商品保留。全量替换会移除未出现商品，需明确确认整个目录范围；先查看移除数量及受影响映射。
5. 选择明确的金额数字格式；底部有汇总时填写结束行。空成本保留缺失，明确零成本与空值不同。公式默认拒绝；可明确接受已有缓存结果，编码始终不接受公式。
6. 点击预览、核对、确认。使用**读取时留存的文件快照**；原文件修改后重新选择。数据库变化或服务重启后重新预览。
7. 可保存格式模板；下次按列名重新定位并核对，模板不授权自动全量替换。导入历史记录来源、文件哈希和口径。

文件限制为 16 MiB、32 个工作表、128 列、25 万数据行、200 万已读取单元格及受限 XLSX 展开大小。通用表需“一行一个销售 SKU，已有该 SKU 基础成本”；不自动换币种、拆整箱成本或计算未知组合明细。

聚水潭普通＋组合表预设保留在折叠区域，沿用既有组合折叠规则；支持唯一识别的工作表、表头移动及列重排，时间列不再必填。两表仍须为同次完整导出，文件日期相同不能证明同一批次。

## 新版源码：连接与配置

- 同步更新成本助手源码和扩展（扩展版本 `0.1.1`，ID 保持不变）。扩展首次使用需核对管理台后，点击“连接当前成本目录”并确认；旧版缺少身份的服务会提示版本不匹配。
- 后台重启后，扩展自动探测同目录服务并重新查询；其他目录或环境会暂停显示成本，需人工核对后重新连接。关闭独立窗口会停止它拥有的后台，平台页面仍开着不能保持后台运行。
- 健康检查不扫描全库；概览统计按修订刷新，尚未更新时显示“待刷新”。断连、恢复中、错库、来源拒绝和扩展通信失败分别显示，旧启动/旧数据响应不会用于当前比较。
- 运费草稿与正式计算共用 Decimal；地区按精确文本匹配，无地区时显示基础规则，空重量标记按首重估算。新增地区金额留空，明确填写 `0` 才代表零金额。
- 运费模板修改先显示前后规则及引用范围；停用模板不能新增绑定。商品每页 100 个，翻页/筛选清空勾选。费率页区分当前、历史、未来；类目可覆盖数不代表实际命中数。
- 保存成功与刷新失败分开提示；遇到返回中断先核对更新历史，不要重复提交。未完成发布时只读查询和新写入暂停，恢复材料保留；重启会先恢复。最新历史若备份缺失，界面不提供回滚。

此前源码回归未使用真实成本数据、真实平台页面或干净 Windows。0.2.0 构建从 schema 创建空白种子，不读取开发业务库；冻结入口和本机安装同步的实际证据单列在项目状态中。

## 安装

给其他电脑使用时，只分发完整的 `dist/CostAssistant-Package.zip`。目标电脑需要 Windows 10/11、Microsoft Edge 和 Edge WebView2 Runtime，不需要 Python、Node.js 或开发工具。缺少 WebView2 时，从 [Microsoft Edge WebView2](https://developer.microsoft.com/microsoft-edge/webview2/) 安装 Evergreen Runtime 后重试。

1. 完整解压 `CostAssistant-Package.zip`。
2. 双击包内 `Install-CostAssistant.cmd`。
3. 安装器完成运行时检查、客户端和扩展复制、扩展文件校验，并打开 Edge 扩展管理页。
4. 第一次使用时，在 Edge 扩展管理页加载安装器复制到剪贴板的目录：`%LOCALAPPDATA%\CostAssistant\browser_extension`。
5. 双击桌面上的 `Cost Assistant`，确认运行概览显示服务已就绪。
6. 刷新抖店活动页即可查看只读成本夹板。

更新时再次运行同一个安装器，然后在 Edge 中对已有扩展卡片执行重新加载。安装和更新会保留本机商品、店铺映射、日志和备份数据。

## 每日成本更新

1. 打开桌面 `Cost Assistant`。
2. 进入“今日成本更新”。
3. 选择同一天的一份普通商品表和一份组合商品表。
4. 点击“只读预览”，确认商品数量、空成本和冲突均符合预期。
5. 确认无误后点击确认更新。系统会重新校验文件、创建备份，并用一个事务发布 SQLite 和启用商品 Excel。

历史正式包成本输入使用聚水潭普通商品表和组合商品表；两份文件须为同次完整导出。项目中的 9.5 文件属于历史业务数据，不能用作测试样本或新的分发种子。

分发包内的 `seed_data` 是空白初始化库和空白成本表，只用于首次安装。升级仅在目标文件缺失时补充，不覆盖已有成本、映射或配置。首次使用需导入成本表和店铺映射表。

## 每日店铺映射

1. 进入“抖店商品对应关系”。
2. 输入或选择明确的店铺名称。
3. 选择该店铺的完整抖店商品导出表。
4. 先执行只读预览，确认精确匹配、待核验、新增、更新和移除数量。
5. 确认后，系统只替换该店铺的映射，其他店铺保持不变。

系统只接受抖店 `商家SKU编码` 与聚水潭商品编码逐字符相等的映射。商品名称、规格、价格和相似度不会被用来猜测编码。

V2 开发板要求抖店商品表同时提供商品类目。导入预览会显示类目完整/缺失、基础费率已匹配/未配置/已停用数量；这些指标只统计精确映射行且不阻止映射导入，类目也不改变现有严格的 SKU 编码匹配规则。

## 抖店夹板

扩展只支持抖店活动页和商品编辑页的只读辅助。打开商品的 SKU 侧栏后，扩展读取当前页面区域中的平台 SKUID 和“最低到手价”，查询本机映射和成本，并按组件显示聚水潭成本、运费、基础服务费和缺失原因。扩展不会报名、改价、保存、发布或提交抖店业务操作。

历史 V1 的“较成本涨跌率”曾按未计运费的成本对比计算：

```text
涨跌额 = 最低到手价 - 聚水潭成本价
较成本涨跌率 = 涨跌额 / 聚水潭成本价 × 100%
```

V2 已采用地区 + 重量的运费模板，并通过“店铺 + 商品ID”绑定。扩展按组件展示聚水潭成本、估算运费、基础服务费和真实成本；缺失组件明确显示“未找到/未配置”，不会按 0 计算。

V2 的预计使用流程为：

```text
导入聚水潭成本
→ 上传带类目的抖店商品表
→ 导入官方费率目录并核对经营大类
→ 配置运费模板、商品绑定和商品重量

→ 在插件查看成本拆解
```

当前模板结构可以表达基础价格和特殊地区独立价格，暂不表达“不发货/禁运地区”。特殊地区金额未获用户确认前不预置。

## 更新历史与恢复

“更新历史”记录商品和店铺映射更新；开发板也记录基础服务费和运费模板更新。系统只允许回滚全局最新一次成功的系统更新；回滚前会检查备份和数据库完整性，并在完成后刷新状态、历史和日志。

默认卸载只移除客户端、快捷方式和扩展目录，保留 SQLite、Excel、日志和备份。卸载客户端可在 PowerShell 中运行 `.\Install-CostAssistant.ps1 -Uninstall`；只有明确需要删除数据时才追加 `-RemoveData`，并先确认目标目录。

## 排障

- Edge 扩展没有卡片：重新运行安装器，在 Edge 扩展管理页加载 `%LOCALAPPDATA%\CostAssistant\browser_extension`。
- 扩展版本不一致：使用同一个安装包更新客户端和扩展，再对扩展卡片执行重新加载。
- 成本服务不可用：先确认桌面 `Cost Assistant` 的运行概览和本机服务连接；如果桌面正常而扩展单独显示不可用，优先按问题记录检查扩展刷新并发、批次超时和状态显示，不要把商品单项未配置当成本机服务故障。
- WebView2 缺失：安装 Microsoft Edge WebView2 Evergreen Runtime 后重新运行安装器。
- SmartScreen 显示未知发布者：当前内部包尚未签名，只在确认包来源可信时运行。

## 开发入口

源码主要位于 `cost_sync/`、`browser_extension/` 和 `windows/`。开发环境可运行：

```powershell
python -m unittest discover -s tests -v
Set-Location browser_extension
npm test
npm run test:layout
```

当前 V2 正式包固定为七个桌面页面：运行概览、今日成本更新、抖店商品对应关系、更新历史、运行日志、基础服务费和运费模板。

V2 正式包已经包含基础服务费和运费模板管理页面。

开发板源码共八页，比正式包多一个“人工核验”页，用于处理待核验与跨店冲突；该页及其前端资源由正式构建脚本移除。正式包保留“基础服务费”和“运费模板”页面。

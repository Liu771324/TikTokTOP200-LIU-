# 商机词与罗盘搜索词双链路采集系统：详细技术文档

> 文档状态：已实现；2026-09-15 已完成最新真实 Edge 全流程验收
>
> 项目目录：`Search term`
>
> 目标：按选品表中的核心商品词，串行采集商机中心商机词和抖音电商罗盘搜索词分析数据，并写入同一个结果 Excel。
>
> 用户侧操作说明见《[项目文档-商机词与罗盘搜索词双链路采集](./项目文档-商机词与罗盘搜索词双链路采集.md)》。

## 1. 项目目标与边界

系统处理网页上传的 `.xlsx` 选品表格。每个热门搜索词按照表格顺序，串行执行两条采集链路：

```text
选品表原始词
  ↓
核心词提取与同词合并
  ↓
商机中心：搜索核心词 → 提取全部商机词 → 读取商品类目
  ↓
抖音电商罗盘：选择行业类目 → 搜索核心词 → 提取全部搜索词分析
  ↓
结果 Excel 的两个工作表
```

当前范围：

- 本地网页上传、任务进度、历史结果和下载。
- 真实 Edge CDP 浏览器自动化。
- 商机中心和罗盘都处理全部可用分页。
- 生成一个新的带时间戳 Excel，不修改输入 Excel。
- 保存主结果和未处理记录；不在用户结果表展示页码、运行状态。

当前不在范围：

- 商品图片、商品链接、店铺信息和其他未约定指标。
- 绕过登录、验证码、风控或平台访问限制。

## 2. 技术约束

### 2.1 浏览器与登录

- 使用用户已经登录的真实 Microsoft Edge。
- 通过 `playwright-core` 的 `chromium.connectOverCDP()` 连接 `http://localhost:9222`。
- Edge 必须使用非默认用户数据目录，例如 `%TEMP%\edge-debug`。
- 登录、扫码和验证码由用户完成。
- 禁止复制、导入、解密或迁移 Cookie，禁止用 Playwright 自带 Chromium 代替真实 Edge 登录。
- 页面操作使用 DOM、可访问名称、文本和结构定位，不使用截图坐标作为业务选择器。
- 与“商机中心”项目共用端口 `9222` 和 `%TEMP%\edge-debug`。启动后先打开商机中心；确认登录后，按 TOP200 项目的方式在同一 CDP 浏览器上下文创建或复用罗盘目标页，不直接启动独立罗盘登录页。

商机中心已有的 Edge/CDP 约束和历史故障记录：

- [商机中心详细技术文档](../商机中心/详细技术文档-商机中心采集系统.md)
- [商机中心数据采集踩坑记录](../商机中心/商机中心数据采集-踩坑记录.md)

### 2.2 页面稳定性

抖店是 React SPA，页码、旧 DOM 和数据渲染可能不同步。所有页面阶段必须使用以下组合：

```text
固定最小等待
  + 当前页码/行数/卡片数
  + 商品或搜索词内容指纹
  + 有上限的重试
```

禁止仅使用“节点存在”“第一行存在”或“页码已变化”判断页面已经更新。翻页后若页码已经变化但内容指纹仍未变化，只能继续等待，不能再次点击下一页。

## 3. 模块设计

当前模块边界如下：

```text
启动界面.cmd
  └─ app/server.mjs                 HTTP API、上传、任务、Edge/CDP 与下载
      ├─ app/public/                控制台 HTML/CSS/JS
      ├─ .artifact-build/collect_data.mjs   两条链路串行采集
      ├─ .artifact-build/build_output.mjs   Excel 输出与检查
      ├─ app/lib/output-sanitize.mjs        Excel/XML 字符清理
      └─ app/lib/process-error.mjs          子进程错误摘要
```

采集器之间不能共享业务 DOM 选择器。两条链路共享浏览器连接、等待、指纹和重试原则，但各自根据现场 DOM 实现定位。

网页通过以下接口驱动单一任务：

```text
POST /api/upload?filename=选品表格.xlsx
POST /api/jobs
GET  /api/jobs/:id
GET  /api/jobs/:id/download
```

该接口返回或写出：商机词结果、罗盘搜索词分析和未处理记录。具体代码签名以实现阶段为准，但输入层不得把浏览器逻辑写死。

## 4. 输入 Excel 契约

### 4.1 选品词表

网页上传 `.xlsx`；项目根目录文件仅作为示例：

```text
Search term/选品表格.xlsx
```

程序扫描工作表表头，优先使用列名“热门搜索词”，找不到时使用“搜索词”。其他列不参与搜索词生成。空单元格跳过，原始词按首次出现顺序处理。

### 4.2 词根词典

输入工作簿可包含工作表“词根词典”，至少包含两列：

| 原始词 | 核心词 |
|---|---|
| 东北大核桃仁 | 核桃仁 |
| 麻辣多味脱油花生米 | 脱油花生米 |

词典是自动提取的纠偏层：

1. 先对原始词做空格、全半角和常见标点归一化。
2. 如果“词根词典”存在精确映射，优先使用该映射。
3. 没有映射时，使用内置语义规则自动提取。
4. 无法可靠判断产品主体或限定词时，记录未处理原因，不静默猜测。

### 4.3 核心词提取原则

核心词不是简单取最后两个或三个字，而是保留商品身份所必需的语义片段：

- 通常去掉产地、营销、尺寸和泛口味修饰，例如“东北大”“麻辣多味”。
- 保留改变商品身份的加工、状态和形态限定，例如“冻干”“脱油”“去皮”“去核”“夹心”。
- `冻干桑葚`和`桑葚`是两个不同核心词，不能因为共享“桑葚”而合并。
- `脱油花生米`和`花生米`是两个不同核心词；核心词由词典或自动规则明确决定。

同一个核心词的多个原始词组成一个 `CoreGroup`：

```json
{
  "coreTerm": "脱油花生米",
  "sourceTerms": ["麻辣多味脱油花生米"],
  "firstInputIndex": 3
}
```

## 5. 核心词语义匹配

商机中心卡片标题不要求与核心词整句连续相等，但必须满足当前核心词的语义片段要求：

- 宽核心词可以包含更具体的变体。例如核心词“花生米”可以包含“脱油花生米”。
- 窄核心词必须保留自身的限定词。例如核心词“脱油花生米”不能接收只有“花生米”的结果。
- 允许在必要语义片段之间插入修饰词。例如“脱油椒盐花生米”可匹配核心词“脱油花生米”。
- 标题完全没有当前核心词主体或必要限定词时排除。

实现上，核心词需要拆分为“主体词”和“保留限定词”。匹配时主体词必须出现；每个保留限定词也必须出现，并按核心词中的语义顺序出现，中间允许插入其他字符。不要用简单的 `title.includes(coreTerm)` 替代这条规则。

## 6. 商机中心采集流程

正式商机中心入口：

```text
https://fxg.jinritemai.com/ffa/bu/NewBusinessCenter
```

### 6.1 首个核心词

1. 连接已登录的 Edge。
2. 进入商机中心页面。
3. 构造商机中心实际使用的 `/search?clueChannel=bu_all&clueId=<核心词>&source=business_center` 查询 URL。
4. 直接进入查询页，不依赖首页搜索框不稳定的回车事件。
5. 同时确认 URL 的 `clueId` 和卡片标题确实属于当前核心词；结果区未渲染时最多重新加载 3 次。

### 6.2 后续核心词

后续核心词沿用同一正式查询 URL 流程，等待当前查询词和结果区域稳定。每次查询都是明确页面导航，因此不依赖上一个 React 输入状态。

每个核心词开始时必须清理或覆盖上一个核心词的输入状态，并确认结果指纹不再属于上一个核心词。

### 6.3 商品类目读取

每个核心词的商机结果稳定后，先读取商机卡片标题，筛选标题包含当前核心词的卡片，再点击第一个匹配卡片，读取详情抽屉中的完整“商品类目”。例如：

```text
休闲食品 > 坚果炒货 > 核桃仁
```

无关的首卡不会作为类目来源。如果第一个匹配卡片打不开或没有类目，依次尝试后续匹配卡片。使用第一个成功读取到的类目作为当前核心词的罗盘类目来源。所有匹配卡片都失败时：

- 商机中心结果仍然保留。
- 跳过当前核心词的罗盘采集。
- 写入“未处理记录”。

读取类目后关闭抽屉，再开始提取当前页商机词。

### 6.4 商机词与分页

- 提取卡片标题中的商机词，不提取按钮、收藏标签和指标文字。
- 结果按页码、页面顺序和卡片顺序保留。
- 同一核心词下重复出现的商机词不去重。
- 翻页直到下一页按钮不可用或页面明确结束。
- 每次翻页记录当前页码、卡片数量和标题指纹；点击下一页最多一次。
- 页码已变化但标题指纹未变化时继续等待，不再次点击。
- 每次翻页后至少等待 2500 ms，再做下一页判断；实测日志间隔约 2.6–3.5 秒。

商机中心工作表字段固定为：

| 原始选品词 | 核心词 | 商机词 |
|---|---|---|
| 麻辣多味脱油花生米 | 脱油花生米 | 脱油椒盐花生米 |

同一核心词有多个来源时，“原始选品词”用顿号合并。

## 7. 抖音电商罗盘采集流程

罗盘目标页面为抖音电商罗盘的“搜索词分析”页面，页面入口应通过 DOM 导航或稳定 URL 定位，不依赖浏览器标签页序号。

### 7.1 行业类目

商机详情中的商品类目用于确定罗盘行业类目，但不原样选择最后的商品叶子节点。示例：

```text
商机商品类目：休闲食品 > 坚果炒货 > 核桃仁
罗盘选择类目：坚果炒货
```

罗盘类目选择规则：

- 按商品类目路径从上到下匹配。
- 罗盘未直接显示商品类目的首层路径时，依次展开可见根类目，直到目标路径出现；不写死“食品饮料”等单一入口。
- 选择能对应到的行业类目中的“坚果炒货”层级。
- 不继续选择“核桃仁”商品叶子。
- 类目选择完成后确认选择框文本或页面状态确实更新。
- 级联菜单项通过 DOM `click()` 事件触发，不依赖元素在内部滚动容器中的鼠标坐标；选择失败时重载页面并最多重试 3 次。

### 7.2 搜索与数据提取

1. 进入“搜索 → 搜索词分析”。
2. 选择当前核心词对应的行业类目。
3. 在罗盘页面搜索框中输入当前核心词。
4. 等待查询条件和结果表稳定。
5. 提取全部分页。

提交搜索后必须等到 URL 参数 `query_condition` 等于当前核心词的罗盘查询接口返回成功，才读取结果区。接口成功后，数据表和明确的“暂无数据”分别作为完成状态；两者都未出现时视为仍在加载并进入有限重试，避免把慢加载误记成无匹配。

罗盘工作表只保存以下字段：

| 核心词 | 罗盘搜索词 | 排名 | 搜索结果曝光人数 | 搜索人数 | 搜索用户支付金额 |
|---|---|---:|---|---|---|
| 核桃仁 | 山核桃仁 | 2 | 2,500-5,000 | 2,500-5,000 | ¥5万-¥7.5万 |

商品类目和原始选品词只作为内部路由元数据，不写入罗盘结果表。相同罗盘搜索词跨页出现时按页面原样保留。

### 7.3 罗盘分页稳定性

罗盘分页使用与商机中心相同的原则，但页面表格字段不同：

- 动态识别搜索词分析表，不固定表格索引。
- 根据表头映射列，不固定单元格位置。
- 翻页必须同时验证活动页码、完整行数和搜索词指纹。
- 结果未变化时只等待；连续重试仍无法确认时，记录当前核心词的罗盘失败并继续任务。

## 8. 任务顺序、检查点与异常

任务顺序固定为：

```text
核心词 A：商机中心全部分页 → 读取商品类目 → 罗盘全部分页
核心词 B：商机中心全部分页 → 读取商品类目 → 罗盘全部分页
核心词 C：...
```

同一时间只操作一个 Edge 页面，不并发运行两个核心词。

内部检查点按核心词保存，至少包括：

- 输入文件摘要和任务创建时间。
- 已生成的核心词顺序。
- 当前核心词及当前链路。
- 已完成核心词的结果摘要。
- 未处理原因和最后一次错误。

检查点字段不进入用户结果表。重新运行时跳过已完成核心词，失败核心词可重新执行；重跑前清除该核心词的旧结果，避免重复合并。

失败策略：

| 阶段 | 有限重试 | 失败后处理 |
|---|---:|---|
| 搜索框提交/页面跳转 | 3 次 | 记录当前核心词并继续下一个 |
| 商品类目抽屉 | 首个匹配核心词的卡片失败后尝试后续匹配卡片 | 全部失败则跳过罗盘 |
| 商机中心翻页 | 单次翻页 3 次，整段分页最多 3 轮 | 丢弃该轮半截结果并从第 1 页重采；最终失败则记录 |
| 罗盘类目选择 | 3 次 | 记录当前核心词并继续 |
| 罗盘翻页 | 3 次 | 保留已确认数据，记录未完成原因 |

“未处理记录”至少包含原始选品词、核心词和原因。主结果表不填充空的假结果。

## 9. Excel 输出

输出目录：

```text
outputs/商机词与罗盘搜索词-YYYYMMDD-HHmmss.xlsx
```

工作表：

1. `商机词结果`
   - 原始选品词
   - 核心词
   - 商机词
2. `罗盘搜索词分析`
   - 核心词
   - 罗盘搜索词
   - 排名
   - 搜索结果曝光人数
   - 搜索人数
   - 搜索用户支付金额
3. `未处理记录`
   - 原始选品词
   - 核心词
   - 原因

输入 Excel 永远只读。结果写入新的工作簿，并使用时间戳避免覆盖历史结果。

输出工作簿使用深蓝与橙色运营风格；每张结果表包含标题、记录数、生成时间、自动筛选和冻结窗格，并按核心词分组、隔行着色。罗盘前三名高亮，未处理原因使用浅红色提示。

## 10. 可视化控制台

网页界面负责：

- 上传或选择 `选品表格.xlsx`。
- 展示核心词处理进度。
- 展示已完成和未处理数量。
- 提供打开或下载结果 Excel 的入口。

浏览器采集器不依赖上传界面的 DOM。上传文件保存到 `app/runtime/uploads`，每次任务的配置和采集中间数据保存在 `app/runtime/jobs/<任务ID>`，最终文件保存到 `outputs`。

任务日志单行限制为 1200 字符。子进程失败时只保留去除 ANSI 和控制字符后的可读错误摘要，避免第三方 WASM/JavaScript 源码进入界面和任务 JSON。写入 Excel 前再次清理 XML 禁止字符，防止 `Xml_InvalidCharacter`。

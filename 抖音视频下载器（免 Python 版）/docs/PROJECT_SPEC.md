# 项目技术文档与任务规划

更新时间：2026-09-12  
项目名称：抖音视频下载器  
当前阶段：公开视频单条下载、Windows 图形版和免 Python 发布版

## 1. 项目目标

本项目解决一个最小且明确的问题：用户在界面中输入抖音公开视频链接，程序解析页面实际播放的公开视频地址，并将视频保存到用户选择的目录。

后续可能增加视频后处理能力，但“去水印”不属于当前版本功能，也不应与下载流程耦合实现。

## 2. 当前范围与非目标

| 项目 | 当前状态 |
| --- | --- |
| 输入普通抖音链接 | 已支持 |
| 输入多个链接（最多 5 个） | 已支持，5 个独立输入框、每框一个链接，按顺序下载、空框跳过并自动去重 |
| 输入短链接或完整分享文案 | 已支持，程序从文本中提取链接 |
| 公开视频解析 | 已支持，优先使用浏览器读取播放器/网络媒体地址 |
| 视频下载 | 已支持，保存为 MP4 |
| 独立音视频轨道合并 | 已支持，使用 FFmpeg 无损封装 |
| 批量顺序下载队列 | 已支持，单条解析或下载失败不中断后续，结束后汇总成功/失败 |
| 下载进度和日志 | 已支持 |
| 自定义保存目录 | 已支持 |
| 免 Python Windows x64 版本 | 已提供 |
| 账号登录、验证码处理 | 当前不做 |
| 去水印 | 当前不做，列入后续评估 |

明确不做的事项：不绕过登录、验证码、权限控制或付费限制；不上传用户视频；不把任意网站下载能力扩展到本项目。

## 3. 用户流程

```text
在 1~5 号独立链接框各粘贴一个链接（最多 5 个，留空自动跳过）
      ↓
逐框提取、去重并校验 douyin.com / iesdouyin.com 链接，形成顺序队列；非法框定位到具体行并在开始前拦截
      ↓
对队列中的每个链接依次执行以下流程（单条失败只记录并继续下一条）：
      ↓
Playwright 驱动 Edge 打开公开页面
      ↓
读取视频元素、网络响应或页面公开数据
      ↓
确定标题和视频地址
      ↓
Requests 流式下载到 .part 临时文件
      ↓
下载完成后原子替换为 .mp4 文件
      ↓
全部链接处理完毕，汇总成功数量与失败原因
```

解析失败时，程序会记录浏览器错误并尝试页面源码解析；两种方式都失败时显示可读错误，不生成空文件。

## 4. 技术架构

### 4.1 运行时

- Python 源码版：Python 3.10+、Tkinter、Requests、Playwright。
- 免 Python 版：PyInstaller 打包后的单文件 EXE；目标电脑不需要安装 Python、Requests、Playwright 或 FFmpeg，FFmpeg 会随 EXE 打包。
- 发布版优先使用目标电脑已有的 Microsoft Edge。开发环境若没有可用 Edge，可安装 Playwright Chromium 作为备用。

### 4.2 模块职责

| 文件 | 职责 | 是否发布必需 |
| --- | --- | --- |
| `douyin_downloader_gui.py` | GUI、链接校验、页面解析、下载和错误提示 | 是 |
| `requirements.txt` | Python 开发依赖清单 | 源码版需要 |
| `start_douyin_downloader.bat` | Windows 源码启动入口 | 源码版需要 |
| `build_exe.ps1` | PyInstaller 构建入口 | 构建机需要 |
| `DouyinVideoDownloader.spec` | PyInstaller 的可复现配置 | 构建机建议保留 |
| `ffmpeg.exe` | 源码版音视频轨道合并组件 | 构建机需要 |
| `免Python版使用说明.md` | 目标电脑使用和故障排查 | 是 |
| `THIRD_PARTY_NOTICES.md` | FFmpeg 和 imageio-ffmpeg 声明 | 发布时建议保留 |
| `dist/` | 本地构建输出，含 EXE | 发布前保留 |
| `release/` | 对外分发目录和 ZIP | 是 |

### 4.3 关键实现约束

- 只接受 `douyin.com` 和 `iesdouyin.com` 域名，避免把用户输入直接扩展为任意地址下载器。
- 视频地址只保留抖音公开视频 CDN 或 `/aweme/v1/play` 地址，并过滤 `blob:` 和页面测试资源。
- 页面使用独立音视频轨道时，分别下载 `media-video-*` 和 `media-audio-*`，再用 FFmpeg 进行不重编码封装。
- 下载使用 `.mp4.part` 临时文件，成功后才改名，失败时清理临时文件。
- 已存在同名文件时自动追加 `_1`、`_2`，不覆盖原文件。
- 浏览器解析在工作线程中执行，界面更新通过 Tkinter 的主线程回调完成。
- 页面首次加载后可能发生二次导航；读取播放器元素时对短暂的执行上下文失效进行重试。
- 界面提供固定 5 个独立链接框，每框期望一个链接（也兼容粘贴整段分享文案），空框跳过、跨框去重，最多提交 5 个；某框为非抖音链接时定位到具体行，并在开始下载前拦截。
- 批量队列只在工作线程内顺序执行，不并发打开多个浏览器页面。
- 批量过程中单条链接的异常被捕获并记录，不中断后续链接；不再逐条弹窗，统一在全部结束后汇总成功/失败。

## 6. 错误处理约定

| 场景 | 用户可见行为 |
| --- | --- |
| 未输入链接 | 弹窗提示先粘贴链接 |
| 链接不是抖音域名 | 拒绝处理并提示支持的域名 |
| Edge 不存在或无法启动 | 提示安装/更新 Microsoft Edge |
| 页面超时 | 提示检查网络后重试 |
| 视频失效、受限或出现验证码 | 提示先确认浏览器能公开播放 |
| 下载中断 | 删除 `.part` 文件，保留已有文件不变 |
| 保存目录不可写 | 显示系统错误，用户可换目录重试 |

## 7. 安全、隐私和合规

- 程序只处理用户主动输入的链接和用户选择的本地保存目录。
- 不要求账号密码，不保存 Cookie，不上传本地视频，不包含遥测功能。
- 下载请求会携带页面地址作为 Referer，这是公开页面媒体请求的常见兼容要求。
- 只应处理自有或获得授权的内容，并遵守平台条款、版权和隐私要求。
- 后续若增加后处理功能，默认保留原视频，不覆盖源文件，并在界面中明确提示处理结果可能有质量损失。

## 9. 测试与验收标准

### 当前验收标准

- 运行源码版或 EXE 后能打开 GUI。
- 合法公开抖音链接能够解析并下载非空 MP4。
- 页面发生一次二次导航时不会因执行上下文失效立即报错。
- 非抖音链接会在下载前被拒绝。
- 一次在多个独立框中粘贴链接时按 1→5 顺序下载，空框跳过、重复链接只下载一次，其中一条失败不影响其余链接；非法链接会定位到具体行并在开始前提示。
- 下载失败不会留下 `.part` 临时文件。
- 同名下载不会覆盖原文件。
- 无 Python 的 Windows 10/11 x64 电脑安装 Edge 后可以运行发布版。

### 推荐测试层级

1. 单元测试：链接提取、域名校验、文件名清理、视频地址过滤。
2. 集成测试：使用公开测试链接验证页面解析和文件下载。
3. 打包冒烟测试：在未安装 Python 的 Windows 环境启动 EXE，检查解析、下载和目录打开。
4. 回归测试：记录曾经触发过的页面导航错误，页面结构或依赖升级后重新验证。

当前项目没有保留独立测试文件；本次清理删除的是缓存、PyInstaller 临时目录和测试下载结果，不影响发布版和构建能力。

## 10. 维护规则

- 页面解析、下载和 GUI 尽量保持职责分离；新增功能优先放在独立函数或模块中。
- 不把账号登录、验证码绕过或任意站点解析加入默认流程。
- 修改解析逻辑后，至少验证一个公开链接、一个非法域名输入和一个失败场景。
- 修改打包依赖后重新执行 `build_exe.ps1`，并在 `release/` 生成新的 ZIP。
- 发布前检查 EXE、使用说明和 SHA-256 校验值，并注明构建日期。

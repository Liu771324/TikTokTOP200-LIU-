## 项目边界

项目负责把聚水潭商品成本或受控商品表导入本机 SQLite，维护按店铺隔离的抖店 SKU 映射，并由桌面管理台和 Edge 只读扩展完成成本查看。

V2 正式包固定包含七个桌面页面：

1. 运行概览；
2. 今日成本更新；
3. 抖店商品对应关系；
4. 更新历史；
5. 运行日志；
6. 基础服务费；
7. 运费模板。

开发板源码共八页。正式包保留“基础服务费”和“运费模板”，只排除“人工核验”页；除非用户明确要求删除，否则后续清理和重构不得把人工核验及其后端流程当作冗余代码删除。

浏览器只读取抖店页面、本机映射和成本，不能报名、改价、保存、发布或提交抖店业务操作。扩展不能使用商品名称、规格、价格或相似度猜测聚水潭编码。

当前 V2 成本来源仍是同一日期的聚水潭普通商品表和组合商品表。正式 API 代码保留为后续设计，当前不得调用正式接口或使用正式密钥。

## 当前计算边界

当前页面显示“较成本涨跌率”，计算未计入运费：

```text
涨跌额 = 最低到手价 - 聚水潭成本价
较成本涨跌率 = 涨跌额 / 聚水潭成本价 × 100%
```

V2 已确认以下业务口径：

- 抖店商品表提供商品类目，类目用于匹配基础技术服务费率；
- 基础服务费不按销量变化，不匹配特定渠道补充费率；
- 运费使用地区 + 重量模板，支持首重、续重和地区价格；模板通过“店铺 + 商品ID”绑定，同商品下全部 SKU 共用，不能用店铺默认模板作为正常兜底；
- 插件使用最低到手价作为基础服务费估算基数；
- 真实成本 = 聚水潭成本价 + 估算运费 + 基础技术服务费；
- 缺少类目、费率、重量或运费模板时，不按 0 计算，按商品组件分别显示“未找到/未配置”；成本价已找到时不能因其他组件缺失而隐藏；
- V2 配置由管理台手动维护，保存必须经过预览、确认、备份和可回滚写入。

开发板保存四级类目时必须保持层级字段独立，不能用 `/` 作为不可逆拼接分隔符；类目变化必须触发店铺映射更新，待核验候选及其人工确认映射必须保留原导入类目。旧数据库迁移和成本快照重建不得丢失类目字段。

基础服务费率同样使用四个独立类目字段，并以 `YYYY-MM-DD` 生效日期保存版本。查询条件为经营大类 + 商品已知类目；官方 `/` 是规则通配符，具体规则优先，末尾连续缺失的商品类目在存在可覆盖父级规则时不能直接判为未配置。取不晚于查询日期的最新版本；该版本被停用时返回“已停用”，不得回退旧版本或按 0 计算。不同生效日期的版本保留为历史，页面区分当前和历史，不以物理删除代替版本管理。新增及启停操作必须追加修改记录，成本快照重建不得丢失费率和记录。

抖店页面即时读取到的类目只作为本次真实成本查询的临时上下文，不自动回写 `douyin_sku_mappings`。商品导入类目必须继续按四个独立字段保存，四级拆分不改变聚水潭成本价按 SKU 编码的关联逻辑。

映射导入预览中的类目和基础费率覆盖统计只计算逐字符精确映射行，并以预览当天的当前生效版本为准。类目缺失、费率未配置或已停用必须明确展示，但不改变严格 SKU 映射的导入资格。

重量只从可确定的规格表达解析，例如 `100g*5袋` 解析为 `0.5 kg`；无重量、体积单位或含多个但关系不明确的重量表达必须保留“实际重量未确定”的来源原因。当前重量是商品净含量，不含纸箱、罐体和填充物；无重量商品的运费按绑定模板首重/首费估算，通用模板为 1 kg / 3 元，界面必须标注“按首重估算”，不能把估算重量写回商品，也不能按 0 元处理。“全国包邮”只是销售说明，不改变内部运费成本。运费模板通过“店铺 + 商品ID”绑定，同一商品下全部 SKU 共用，正常路径不按店铺默认模板兜底。运费模板修改必须沿用预览、确认、备份、事务写入、统一历史和全局最新更新回滚。

当前运费模板数据结构只支持地区价格和包邮，不支持“不发货/禁运地区”；项目验收库已配置全国通用模板，但没有预置特殊地区金额。不得把抖店按件模板静默换算为按重量模板，也不得忽略港澳台、新疆、西藏等禁运口径。必须先取得用户确认，再补齐数据、页面、计算和测试。

扩展左下角“成本服务”只表示本机服务连接状态。页面刷新、批量查询超时或单个商品缺少重量/类目/费率时，不得把全局状态改成“服务不可用”；这些情况必须在商品卡片中分别标记。基础服务费页面必须先展示可操作目录，商品覆盖统计等慢查询异步加载，不能由统计查询锁住整个管理台。

V2 仍不包含销量读取、销量阶梯、特定渠道补充技术服务费、达人佣金、广告费、税费、抖店开放平台自动同步和聚水潭正式 API 同步。

## 修改规则

- 只修改当前任务直接涉及的文件。
- 优先保留现有数据格式、接口边界和页面操作习惯。
- 金额使用十进制计算，不能使用二进制浮点数替代。
- 文件导入必须保持预览、哈希复核、备份和事务发布。
- 映射必须保持逐字符严格匹配，不增加模糊匹配兜底。
- 新功能必须有对应的失败场景和成功场景验证。
- 开发板人工核验页属于现有开发功能，涉及它时要同时核对页面、桥接、候选表、映射写入、备份和更新历史。
- 不修改 `storage/` 中的真实业务数据进行演练；使用临时目录和测试数据。只有用户明确要求真实数据落地时，才允许在指定项目验收库执行预览、备份、事务写入和写后复核。本轮真实映射与费率配置属于该已授权验收任务，不代表可以修改已安装客户端数据。
- 不删除真实数据库、原始业务 Excel、恢复备份、日志或用户资料。
- 重建正式包时必须重新完成包内哈希、安全条目、客户端自检和安装回归。

## 禁止事项

- 恢复已清理的旧浏览器管理入口或本机消息链路；
- 向任意网页开放管理写接口；
- 把开发辅助页面或未验收流程放进 V1 正式包；
- 调用正式 API、泄露正式密钥或发送真实写请求；
- 自动点击、输入、报名、改价、保存、发布或提交抖店页面；
- 为了清理目录删除真实数据、恢复备份、日志或用户资料；
- 不得超出已确认口径自行增加销量、渠道补充费率或其它经营费用计算。
- 不得把基础服务费、运费或其它缺失配置按 0 处理后展示为完整成本。
